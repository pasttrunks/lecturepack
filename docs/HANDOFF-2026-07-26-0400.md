## 10. Lessons — PROMOTE TO SKILLS FOLDER

The Claude Skills folder was **again unreadable** (`…\ECO182\Claude share\Claude share\`
does not exist on this machine), so nothing could be written there. These are recorded in
`BUG_LIST.md` and repeated here verbatim for promotion:

1. **A passing suite is not a reviewed change.** 688 tests passed while three blockers and
   a data-loss bug sat in the diff. The independent pre-release pass is the cheapest
   bug-fix window that exists — and every finding must be **re-verified**, because the
   reviewer will also be confidently wrong sometimes (BUG-18 was).
2. **Verifying both halves is not verifying the seam.** A service tested directly plus a UI
   tested with no backend can both pass while the feature is 100% dead (BUG-09). When a
   handoff says "X and Y verified separately, the integration was never driven", that
   sentence is *naming the most likely bug site*.
3. **A stub can hide the exact bug it stubs.** `test_media_link_adapter.py` monkeypatched
   `QTimer.singleShot` — the very call that was broken — so 20 tests passed for a dead
   feature. When stubbing a delivery mechanism, add one test that exercises the real one.
4. **A hardcoded mirror list is a silent-failure machine.** `bridge.js` duplicates
   `bridge.py`'s signal names; a missing entry fails silently with no error. Derive the
   list from the source of truth in a test, never spot-check N names.
5. **Inserting a method mid-`__init__` orphans everything after it.** Python warns about
   nothing; the class still constructs. An AST guard for "statements after a top-level
   return" catches the whole class.
6. **A previously-measured defect count is a lower bound, never a work list.** "3 contrast
   near-misses" was 11, and the reported worst case wasn't the worst.
7. **Before darkening a text colour, check the reverse direction** — the same token is
   often a background elsewhere.
8. **Fail, don't escalate.** When a safe operation (Recycle Bin) fails at runtime, failing
   is recoverable; silently substituting the unsafe equivalent is not.
9. **Don't edit assets while a bundler runs**, and diff the bundle against source anyway.
10. **Don't drive a GUI with blind `SendKeys`.** A keystroke intended for the app under
    test landed in the user's other application and typed into their text field. Foreground
    the window and verify focus, or verify structurally instead.

## 11. How to run / debug

```
.\.venv\Scripts\python.exe -m pytest -q -p no:faulthandler        # 696 tests, ~3.3 min
.\.venv\Scripts\python.exe -m app.lecturepack_desktop             # run from source
.\.venv\Scripts\python.exe app\packaging\build.py                 # full build (~10 min)
node --check app\ui\app.js                                        # JS syntax gate
```

- **Always** set `LECTUREPACK_DATA_DIR` to a disposable dir for acceptance work.
- **UI verification: use a FRESH PORT every round** and `curl | grep` the served bytes.
  QtWebEngine caches `app.css`/`app.js` hard.
- `?preview=1` now gates ALL demo content. The screenshot pipeline needs that flag.
- Driving the packaged GUI: Windows-MCP's `Click` coordinate param arrives stringified and
  the UI tree cannot see inside `QWebEngineView`. Use PowerShell + `user32.dll`, and
  **always foreground the right window first**.
- The code-review-graph post-commit hook prints a cosmetic `UnicodeEncodeError`; commits
  still succeed — verify with `git log`.
