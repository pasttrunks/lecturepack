## 1. What this project is

LecturePack turns a recorded lecture into a study pack: transcript, slides, grounded
concepts, flashcards, quiz and Teach Me. It ships as a Windows Electron app
(`LecturePack.exe`) with a PyInstaller Python sidecar (`LecturePackSidecar.exe`) carrying
the engine, plus a Cloudflare Worker AI gateway.

**2.0.2 is published and marked Latest**:
https://github.com/pasttrunks/lecturepack/releases/tag/v2.0.2

## 3. What shipped, and the two P0s found on the way

### Group study (the feature)

Lectures are grouped into a subject; the group builds one cross-lecture map as a REDUCE
over the analysis each lecture already stored. Ten lectures cost one request over ten
small summaries, not ten transcripts re-read. Cached on a fingerprint of
`job_id + generated_at`, so a repeat session is free and adding a lecture rebuilds.

### BUG-43 — it could never have worked (P0, two independent faults)

Running the feature against the real gateway for the first time found:

1. **The deployed Worker was stale** — 8 tasks, no `group_analysis`. Live calls returned
   HTTP 400 `unsupported_task`. The inherited handoff claimed the route was live.
2. **The response envelope was never unwrapped.** `GatewayClient.request()` returns
   `{"result": …, "diagnostics": …}` — the documented contract, unwrapped correctly by
   `ai_study_service.py:689`. `group_study.prepare()` handed the whole envelope to
   `normalize()`, which looked for `concepts` at the top level, found none, and discarded
   a correct AI answer as `empty_analysis`.

**Why 1770 tests missed it:** every test mocked the client with a *bare* analysis. The
mocks agreed with each other and with nothing real. Two regression tests now pin the real
envelope; both fail without the fix.

### BUG-42 — the M3 suite tested nothing it claimed to

Four wrong fixture assumptions (hand-rolled `study-content.json` instead of
`study_v2.CONTENT_FILENAME`, a `"pending"` status that `load_content()` normalised to
READY, an assertion that a cleared group key equals `""` when it is popped, and `{"id":}`
where the sidecar reads `request_id`). Details in `BUG_LIST.md`.

### UX repairs

The Study empty states told a student who had studied nothing that they had **cleared
their weak areas** — a subject scope has concepts but no cards or quiz, and "nothing
exists" was rendered as "you finished". Fixed, along with "0 concepts left to review"
under "0% progress" and "Nothing to review, nice work". On Subjects: the mastery
percentage printed twice per card, "Microeconomics" broke mid-word (the Study button was
crowding the title, not a wrapping bug), a long name wrapped to five lines and stretched
its grid row, and the header restated itself over the title.

### Security and infrastructure

- Gateway admin key no longer accepted from the query string (it reached access logs,
  proxies and referrers); comparison is now constant-time.
- `release-electron.yml` no longer dies on a missing `.venv` PyInstaller — but see §7, it
  still cannot build.

## 4. Decisions and gotchas worth keeping

- **ISCC was installed all along**, per-user at
  `C:\Users\marsh\AppData\Local\Programs\Inno Setup 6\ISCC.exe`, not on PATH. Three prior
  sessions reported it missing and skipped the installer.
  `scripts/build_electron_release.py:28` already checks that exact path — the project's
  own builder always could have found it. Recorded in memory as
  `windows-toolchain-paths.md`. **Never report Inno Setup as missing on this machine.**
- **`package-win.mjs` does not invoke Inno Setup**, so the 260-char path trap applies only
  to installer builds. The full builder ran fine from this worktree; `C:\LPB\cand` staging
  was not needed.
- **The gateway ships nothing into the app.** Worker changes never require a rebuild.
- **`verify_release_versions.py` counts five version surfaces**, including
  `package-lock.json` twice. Bumping the three obvious ones fails the build closed.
- **The sidecar IPC wire key is `request_id`, not `id`.** Sending `id` gets silence,
  because `_respond()` returns early.

## 6. NOT verified

- **The in-app updater experience.** The harness drives the updater *module*, not a
  running window, so "the update button appears", "active work blocks the install" and
  "the old app exits cleanly" remain unit-level only. Carried over from 2.0.1.
- **No clean-machine acceptance for 2.0.2** (2.0.1 had one).
- **The gateway admin dashboard was never opened in a browser.** The fragment-stripping
  behaviour is unit-tested only.
- **Flashcards/quiz are never generated for a subject scope.** The UI now says so
  honestly, but the CHANGELOG's promise that they are "generated from this map by the
  existing per-concept tasks" is not yet true at group scope. Nearest open feature work.
- **Not Authenticode signed.** SmartScreen will warn. Accepted, called out in the notes.

## 7. Known issues / residual risks

- **CI cannot build this product and never could.** `bin/` (ffmpeg, ffprobe, whisper-cli,
  the model) is gitignored and no workflow step fetches it, so the release job dies on
  "Required sidecar build input is missing". 2.0.0 and 2.0.1 were therefore also built by
  hand here. **Consequence: releases can only be cut from this one machine.** Fix is to
  host the payload (a GitHub release asset or R2, which this project already uses) and add
  a fetch + checksum step. Roughly half a day. Not a product defect.
- **`gh release create` with ~875 MB of assets times out** and leaves an untagged draft.
  Create the release as a draft with no assets, upload each asset separately, verify, then
  `gh release edit --draft=false`.
- **`main` is still beta-era** (`459faf5`, 0.9.0-beta.5) and contains none of 2.0.x.
- **Twelve worktrees exist**, several on dead branches — a standing source of confusion.
  Pruning was not done; it is the user's call.
- The `code-review-graph` commit hook crashes on a cp1252 `UnicodeEncodeError` after every
  commit. Cosmetic; the commit still lands, but every commit looks like it failed.

## 9. Skills-folder retrospective

Ran the learning loop. Promoted to `lessons/anti-patterns.md`, logged in
`lessons/CHANGELOG.md`:

- **#101** — "not installed" usually means "not where I looked"; per-user Windows installs
  are invisible to PATH and Program Files checks, and that conclusion silently downgraded
  three releases.
- **#102** — when every test for a feature builds its fixture from the same wrong guess,
  the suite's agreement is worthless. Test one real round trip per external contract, and
  treat "it's deployed" in an inherited doc as rumour until a live probe agrees.
- **#103** — an empty state is not a finished state; enumerate why it could be empty
  before writing the copy.

- **Never run anything else while an acceptance or A→B run is in flight.** `detect_orphans`
  does a before/after PID diff, so a concurrent `pytest` looks exactly like leaked
  processes. One A→B run failed this way and passed cleanly when re-run alone.

  was never targeted; every command used an explicit `--data-dir`.
- The runtime-setup gate covers the whole window on first launch. Automation must click
  `#btn-runtime-done` (enabled only once all checks pass) before it can reach the app.
