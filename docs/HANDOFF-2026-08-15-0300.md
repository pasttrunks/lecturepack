## 1. What this project is

LecturePack turns a recorded lecture into a study pack: transcript, slides,
grounded concepts, flashcards, quiz and Teach Me. It ships as a Windows Electron
app (`LecturePack.exe`) with a PyInstaller Python sidecar (`LecturePackSidecar.exe`)
that carries the engine, and an optional Cloudflare Worker AI gateway. Shipped
public release is **2.0.0**; **2.0.1** was a hardening pass tagged but not
published. This session produced a **2.0.2 candidate**, built and acceptance-green,
not yet tagged or published.

## 4. Architecture & decisions

- **`sol/release-polish` is the release line.** Verified by ancestry, not by
  reading docs. Any future "have these diverged?" question should be answered with
  `git merge-base --is-ancestor` and `git log A..B`, which cost nothing and settle it.
- **`package-win.mjs` does not invoke Inno Setup.** So the 260-char path trap
  documented in the 2.0.1 handoff does **not** apply to building the unpacked
  candidate — only to producing the installer. That is why this build succeeded
  from a worktree without staging to `C:\LPB\cand`.
- **The gateway ships nothing into the app.** It is a Cloudflare Worker, so the
  security fixes in `88d7125` did not invalidate the already-acceptance-tested
  packaged candidate. Worth remembering: gateway changes never require a rebuild.
- **New gotcha (BUG-42's lesson).** A fixture that hand-rolls a filename or status
  string the product parses is a test that silently stops testing. Reference the
  product's own constant so a rename breaks it loudly. And a fixture that stubs the
  transport (`_respond`) cannot prove the wire protocol — only the packaged
  end-to-end test can, which is why its failure was the one telling the truth.

### A methodology note worth keeping

The first A→B run reported **FAIL** on an orphan `python.exe`. That was not a
product bug and not a harness bug — a full `pytest` suite was running
concurrently, and `detect_orphans` does a correct before/after PID diff, so the
pytest subprocesses looked exactly like leaked ones. Re-run with the machine
quiet: PASS, zero orphans. **Never run anything else while an orphan/process
check is in flight**, and do not dismiss such a failure as flaky — re-run it
clean and let it say PASS itself.
