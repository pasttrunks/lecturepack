## 1. What this project is

LecturePack turns a lecture recording into a study pack: transcript, detected slides,
and an AI-generated set of concepts, flashcards, quiz questions and Teach Me material,
every answer cited back to a timestamp or slide. It is a Windows desktop app —
Electron 43 shell, PyInstaller Python sidecar, plain HTML/CSS/JS in `app/ui` with **no
build step** — talking to a Cloudflare Worker gateway (`ai-gateway/`) that fans out to
NVIDIA, Workers AI and OpenRouter. Version 2.0.1 is acceptance-green and unreleased,
blocked only on an Authenticode certificate. Work happens in the worktree
`C:\Users\marsh\Documents\LecturePack-worktrees\release-polish` on branch
`sol/release-polish`.

## 3. What this session did

### 3.1 Drag-and-drop inside the app (`eea00ae`)

**Symptom:** "drag and drop doesn't work from inside the app." **Root cause:** the only
in-app drag is lecture card → Process, gated on `_jobIsReady()` = status `'queued'`,
meaning imported-but-never-processed. Every lecture in a normal library is `done`, so no
card ever got the `draggable` attribute, and `_queue_existing_jobs` refused `done` at the
sidecar too. Not a regression — a feature scoped to a state libraries pass through in
seconds, with nothing saying so.

**Fix (user chose "re-process"):** finished/failed/cancelled/interrupted lectures are now
draggable; dropping them on Process re-runs the pipeline behind a confirm dialog naming
what will be overwritten. Stages reset *after* a successful enqueue so a rejected queue
leaves the finished job intact. `_jobIsReady` is untouched — it still governs the
Start/Options row, and widening it would have put a Start button on every finished
lecture.

**The interesting part:** the renderer sent `reprocess`, the sidecar accepted it, and the
bridge silently deleted it. `mapCall` in `electron-bridge.js` rebuilds every payload from
named keys, so an unlisted key vanishes — and the response came back `ok: true` with
`reason: "done"`, indistinguishable from a deliberate refusal. Found by driving a real
mouse drag over CDP against the packaged app, not by reading.

### 3.2 The guided demo (`247f50e`)

**Two slides instead of four.** `PRESETS["demo"]` (`constants.py:139`) was written and
calibrated for the bundled 10-second lecture, but nothing could select it: `_preset()`
whitelists conservative/balanced/detailed and silently returns `balanced`, whose
`min_time_between_slides: 5.0` admits the first slide and then one more. Measured on the
bundled video: balanced 2 (1.5s, 9.5s), detailed 2, demo 4 (0.75s, 4.0s, 6.5s, 8.75s).

Setting the preset at import was **not enough** — the bridge always sends a preset with
`start_processing`, and `_start_job` applied it unconditionally, overwriting `demo` with
`balanced` the instant the job began. Both halves are needed. Verified 4 in the packaged
app.

**Study now instant.** `app/assets/demo/study-content-v2.json` ships a pre-built pack,
adopted by `_adopt_demo_study_cache` before generation starts. It is a cache, not a fake:
genuine pipeline output, regenerable via `scripts/capture_demo_study_cache.py`. Guarded
on the demo video's SHA-256 plus the transcript and slide counts the positional citations
were captured against; any mismatch builds normally. `force=True` (Regenerate) always
bypasses it.

**Also:** removed the Archive and Restore buttons from the Home action bar. Permanently
disabled, no handler, no sidecar command, tooltips still reading "not available in Beta
15" in a 2.0.1 build.

### 3.3 Study pack expansion was dead everywhere (`db1435e`) — the big one

**Every Study pack ever generated has been stuck at the generator's schema minimum: 2
flashcards, 3 questions.** The expansion pass failed at two gates, both introduced by me
earlier in this same release cycle:

1. `expand_concept_material` was never added to `TASK_TYPES` in `ai_gateway.py`, so
   `GatewayClient.request` raised `ValueError` before any network call.
2. The gateway task — schema, instruction, 3500-token budget — was written in `959b101`
   and **never deployed**. The live Worker answered "This Study task is not supported."

Both are silent by construction: expansion runs after the pack is marked ready, inside
`except Exception: continue`, so a dead task is indistinguishable from a model with
nothing to add. The earlier "2 → 18 flashcards" claim in the previous handoff is **wrong**
— it exercised the local path, not the round trip. This is the true cause of the "Study
is too limited" complaint that opened the session; the UI symptoms were fixed earlier
while the cause stayed in place.

Deployed the Worker (`c0781884`) and allowlisted the task. Measured live on the demo
lecture: 2 → 9 flashcards on a direct probe; a full capture went 2/2/3 → 2 concepts, 10
flashcards, 7 quiz questions spanning three difficulties and all three question types.

`tests/test_gateway_task_allowlist.py` now derives the allowlist from the actual call
sites and cross-checks it against the gateway's own task list, so neither half of the
round trip can silently drop a task again.

**Also:** the demo capture now forces vision over every slide. Vision runs only on slides
the analysis asks about and it asked for none, so slides 2 and 4 — whose facts exist only
as on-screen text — were absent from the pack entirely. Capture-time override only; the
running app is unchanged.

### 3.4 Group study foundation (`27dfbea`)

New `lecturepack/services/group_study.py` plus a `group_analysis` gateway task. Builds
one cross-lecture map for a group: merged concepts tagged with their source lectures,
relationships marked when they cross lectures, through-lines, and gaps.

## 4. Architecture & decisions

### The group reduce is over work already done

Every lecture persists its own `lecture_analysis` (summary, concepts, relationships)
inside `study-content-v2.json` at processing time — about 1KB on the bundled demo. That
is the *map* half of a map-reduce, already computed. So group study is **one request over
N small summaries**, not N transcripts re-read. Flashcards/quiz/Teach Me are then
generated from that map by the existing per-concept tasks, which keeps every individual
request far from the route budget that took Study down in production.

Cache fingerprint is job id **plus each lecture's pack `generated_at`**, so re-processing
one lecture invalidates a group map that quoted it. Order-normalised: reordering the
library is not a content change.

`group_analysis` is the only task pointed at a stronger model, via the existing per-task
env vars (`OPENROUTER_GROUP_ANALYSIS_MODEL`), and is deliberately **absent** from
`NVIDIA_FIRST_TASKS`: it runs once per group and is cached, so the better answer is worth
more than the faster one. An 8B model is the wrong tool for deciding which concepts
across ten lectures are the same idea.

### Rejected alternatives and the evidence

- **Raising `study_material_generation` to ask for a bigger pack in one call.** Already
  tried and reverted earlier in this cycle: 16000-token ceiling → `provider_timeout` then
  `provider_invalid_shape` from truncated JSON, HTTP 503, Study AI down in production.
  The comment at `tasks.js:235` exists to stop the next person retrying it. Expansion
  across many small calls is the answer, which is why §3.3 matters so much.
- **Widening `_preset()` to accept `"demo"`.** Rejected: it would make an internal
  calibration profile selectable as an ordinary processing option. Forced at the demo
  branch instead.
- **Making the demo pack bigger by hand.** Rejected: a 10-second clip yields a 2-segment
  transcript, and padding beyond what the lecture supports is fabrication. The pack grew
  only because expansion and vision started genuinely working.
- **Capturing the demo pack by running the guided demo in the app.** Does not work — demo
  jobs are deleted on completion by the demo lifecycle, taking the artifacts with them.
  Hence the standalone capture script against a scratch data dir.

### New gotchas

- **`electron-bridge.js:mapCall` is an allowlist, not a pass-through.** Any new payload
  key must be named there or it is dropped in silence. Cost hours this session.
- **A value set at import can be overwritten at start.** `_start_job` re-applies
  `preset` and `product_mode` from the payload on every start.
- **`except Exception: continue` around a gateway call hides programming errors as
  cleanly as it hides model failures.** Two gates of a dead feature survived weeks
  behind one.
- **Claude Design remains strong on design, unreliable on diagnosis.** This session it
  claimed `--shadow-ink` is invisible on dark panels at 1.26:1; it is `#000000` in the
  dark block, but `app.css:213` documents the opposite conclusion with reasoning. Its
  design decisions were sound; verify its causal claims every time.

## 10. How to run / debug (quick)

```bash
# Tests (from the worktree root)
.venv\Scripts\python.exe -m pytest tests/ -q

# Gateway checks and deploy
cd ai-gateway && npm run check && npm test && npx wrangler deploy

# Regenerate the demo Study pack (needs the live gateway + local whisper/ffmpeg)
.venv\Scripts\python.exe scripts\capture_demo_study_cache.py

# Launch the packaged app with CDP for Playwright driving
electron-spike\dist\LecturePack-win32-x64\LecturePack.exe --remote-debugging-port=9333
```

- **Data lives in** `C:\Users\marsh\LecturePackData` (`data_directory` in `config.json`);
  jobs under `jobs/<job_id>/`, group maps will land under `groups/<hash>/`.
- **Sidecar self-test:**
  `resources\LecturePackSidecar\LecturePackSidecar.exe --self-test --data-dir <tmp>`
  prints a full component checklist and is the fastest way to prove a build is sane.
- **Gateway URL** is `https://lecturepack-ai-gateway.discordsammy2.workers.dev`,
  overridable with `LECTUREPACK_AI_GATEWAY_URL` for staging.
- **Rebuilding the sidecar:** `cd electron-spike && node package-sidecar.mjs`, then copy
  `dist-sidecar/LecturePackSidecar` over `dist/LecturePack-win32-x64/resources/LecturePackSidecar`.
  Kill every `LecturePack*` and `whisper-cli` process first or the copy fails with EPERM.
- **Driving the packaged UI:** Playwright `connect_over_cdp("http://127.0.0.1:9333")`;
  `window.lpBridge.call(command, payload)` from the page reaches the sidecar directly and
  is the fastest way to test a backend change without clicking.
