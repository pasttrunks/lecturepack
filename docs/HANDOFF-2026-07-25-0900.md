## 4. What was done

### `ccef784` — WCAG AA in the light theme (owner said "fix them properly")

The previous handoff left three light-theme "near-misses" for an owner decision. Asked;
the answer was to fix them. **The three were an under-count: a full weight/size-aware
sweep of the light palette found 11 failing pairs.** `--muted` failed on *all four*
surfaces it is used on (worst 3.26, and the reported 4.35 was not even the worst case),
and six badges failed as text on their soft backgrounds.

Four light tokens were darkened by the smallest hue- and saturation-preserving step
(HLS lightness ×0.825–0.930) that clears 4.5:1 on every surface each is used on:
`--muted` `#8A8173`→`#726A5F`, `--green` `#128A52`→`#107847`, `--red` `#D63A2C`→`#BA3024`,
`--orange-ink` `#C6430E`→`#B83E0D`. Dark theme was already at 0 failures and is untouched.

**This also surfaced an older, missed instance of BUG-05.** Checking the reverse direction
(these tokens are also *backgrounds*) revealed that the original sweep grepped `color:#fff`
and therefore never saw **icons**, which set colour via an SVG `stroke` attribute. All five
surviving sites sat on a saturated fill and all five failed the 3:1 graphical floor —
white on dark-theme `--green` was **2.06**. They now use `var(--on-signal)`; the two green
tick circles moved to `--green-fill` so the ink stays legible against the now-darker
`--green`.

### `e084133` — BUG-09: worker-thread signals never delivered

See the BUG-09 entry in `BUG_LIST.md` for the full write-up. Short version:
`_emit_soon` used `QTimer.singleShot(0, lambda: signal.emit(data))`. **That overload starts
the timer in the calling thread.** The callers are plain `threading.Thread` workers with no
Qt event loop, so the timer never fired, the functor never ran, and the signal was never
emitted. Since the worker's own `try/except` completed successfully, nothing was logged —
a silent hang, empty stderr.

Killed `media_probe`, `media_progress`, `media_done`, and the post-download handoff to
`import_video`. Fix: pass a main-thread QObject as the context argument at both sites.

## 8. Known issues / residual risks

  `QTimer.singleShot` itself, so all 20 of its tests passed for a feature that was

**PROMOTE TO SKILLS FOLDER** (verified in this project, this session):

1. **Verifying both halves is not verifying the seam.** A service tested directly plus a UI
   tested with no backend can both pass while the feature is 100% dead. When a handoff says
   "X and Y verified separately, the integration was never driven", that sentence is
   *naming the most likely bug site* — treat it as a lead, not a coverage footnote.
2. **A silent hang with empty stderr means the code never ran, not that it failed.** If a
   broad `try/except` logged nothing, stop hunting a swallowed exception and ask what was
   never invoked. Qt-specific: `QTimer.singleShot(0, fn)` without a context QObject starts
   the timer in the *calling* thread and never fires from a plain worker thread.
3. **A stub can hide the exact bug it stubs.** Monkeypatching the transport (here
   `QTimer.singleShot`) makes every test above it pass regardless of whether the real
   transport works. When stubbing a delivery mechanism, add one test that exercises the
   real one.
4. **A previously-measured defect count is a lower bound, never a work list.** A tidy list
   of "3 remaining contrast near-misses" was 11, and the reported worst case wasn't the
   worst. Re-run the full sweep from source values every time, before and after.
5. **Before darkening a text colour, check the reverse direction.** The same token is often
   also a background elsewhere; that is how a five-site icon-contrast defect surfaced that a
   `color:#fff` grep had missed for an entire prior pass.
6. **Don't edit assets while a bundler is running,** and diff the bundle against source
   afterwards regardless. PyInstaller collected `app.css` after an edit and `app.js` before
   it, producing a half-updated bundle that looked fine.

## 11. How to run / debug

```
.\.venv\Scripts\python.exe -m pytest -q -p no:faulthandler        # 677 tests, ~3.3 min
.\.venv\Scripts\python.exe -m app.lecturepack_desktop             # run from source
.\.venv\Scripts\python.exe app\packaging\build.py                 # full build (~10 min)
node --check app\ui\app.js                                        # JS syntax gate
```

- **Always** set `LECTUREPACK_DATA_DIR` to a disposable dir for any acceptance work.
- **UI verification: use a FRESH PORT every round** (`python -m http.server <PORT> -d app/ui`)
  and `curl | grep` the served bytes to confirm your edit is actually being served.
  QtWebEngine and the in-app browser cache these assets hard.
- **Driving the packaged GUI:** the Windows-MCP `Click` tool's coordinate parameter did not
  work in this session (the list arg arrived stringified) and the UI tree cannot see inside
  the `QWebEngineView` anyway. Fall back to PowerShell + `user32.dll`
  `SetCursorPos`/`mouse_event`, and `System.Windows.Forms.SendKeys` for typing. That worked
  reliably.
- To exercise link import safely: `ffmpeg -f lavfi -i testsrc=...` a clip, serve it with
  `python -m http.server`, and paste that localhost URL. yt-dlp handles it via the Generic
  extractor. Never test with third-party content.
- The code-review-graph post-commit hook still prints a cosmetic `UnicodeEncodeError` on
  Windows; **commits still succeed** — verify with `git log`.
