## 2. MOTION SYSTEM v2 — mechanical (replaces v1)

The prior pass's vocabulary was generic fade+rise everywhere and reached only part of the UI.
Owner feedback: the screen transition "flash" was too intense in dark mode, and they were
"not impressed by the animations overall".

**Diagnosis** (both real, both measured):
- Every navigation ran TWO stacked animations: the root View Transition faded the whole page
  `0 → 1` while `main [data-screen]` ran its own opacity ramp on top — ~10px of stacked
  travel and two opacity ramps per nav. Dark mode amplified it because a bright panel
  emerging from opacity 0 against a near-black background is a much larger luminance jump.
- The vocabulary itself was the problem, not the tuning.

**What v2 is:** objects have mass and hard edges, travel on ONE axis, and stop hard.
- `--motion-spring` (critically damped, no overshoot) is the single movement curve.
  `--motion-ease` is demoted and **banned on opacity**.
- Every entrance keyframe is transform-only: `lprail` (screens, 10px X), `lpseat`/`lpseat-sm`
  (6px/3px Y), `lpdrop` (14px, the completion reveal). **Exactly one** opacity keyframe
  survives — `lpsupport` (floor `.7`) — so "opacity is support, never the effect" is enforced
  structurally rather than remembered.
- **The View Transition layer was REMOVED.** No element ever set `view-transition-name`, so
  there were no shared-element transitions to gain; the UA's default root transition IS the
  crossfade being removed; and its async callback caused the indicator bug (§3). `nav()` is
  now synchronous. Deleted with it: `lp-vt`, `lpvtout`/`lpvtin`, `.lp-flip` +
  `LP.motion.flip` (dead, and unworkable since `renderQueue` replaces rows wholesale), and
  `scale()` on bordered modals.
- New durations `--motion-snap:110ms` / `--motion-seat:140ms`; `--motion-normal` is now
  documented as colour/state only.

**Verified in the real Qt WebEngine over CDP:** the screen rule animates `lprail` only and
computed opacity stays `1.0` across all 26 sampled frames — there is no luminance ramp in
the navigation path in either theme, so a flash is structurally impossible, not merely
softened.

## 3. Button character — the language reaches all 88 buttons

Before: the design language lived on 25 `.lp-press` buttons; the other 63 had
`:hover{translateY(-1px)}` and nothing else.

**The load-bearing constraint:** 75 of 88 buttons carry an inline `border`/`background`/
`color`, and inline beats a class rule regardless of pseudo-class (BUG_LIST lesson #9). So
the character is built from **`box-shadow` + `transform` only** — inline on just 2 and 1
buttons respectively. Consequence worth keeping: because `border-color` is never touched,
buttons with orange/red/teal inline borders keep their identity instead of being flattened.
Total `!important` in that block: **1** (a reduced-motion transform).

- Hover materialises a pitch-black hard edge; press drives the slab in with an inset.
- **No pale outlines anywhere.** `--line` in dark is `#4E5563` — lighter than `--panel` — so
  every neutral resting `--line` border read as a white outline and is now `transparent`,
  materialising on hover. Signal-coloured borders untouched.
- Sidebar nav included (owner explicitly asked): no resting border, hard dark edge + fill +
  shadow + `translateX(2px)` on hover, and **the icons LEAD the slab** (icon steps another
  2px inside it, so it arrives first); the active item's icon sits proud at `scale(1.14)`.
- The sidebar "No lecture loaded" chip is now a real button: routes to Review with a lecture
  loaded, or Home with the import card re-announced when empty.

**Sweep methodology matters here.** My first sweep queried
`document.querySelectorAll('button')` and reported "zero pale borders" — but interactive
`<label>`/`<span>` elements were invisible to it. Widening it found the output-mode labels,
the slide-sensitivity spans, and `#compute-cuda`/`#compute-gpu`. **Any future audit of
interactive elements must not filter by tag name.** Also: pale borders hid in THREE places —
CSS rules, runtime `style.cssText`, and inline `style.borderColor` written by JS
(`reflectBackend`, `reflectEngine`, the Smart Study preset generator). Only a live-DOM sweep
finds the last kind; 125 buttons render at runtime vs 88 in the markup.

## 4. Dark palette

Surfaces were lightened so a pitch-black shadow reads at all (it measured **1.26:1** against
`--panel`), then stepped back down twice on owner feedback. Final: `--bg #16191F`,
`--panel #1F242C`, `--panel2 #262C35`, `--sunk #1A1E24`; shadow now ~1.35:1.

`--muted` (`#8C93A2 → #A3AAB8`), `--nav-ink` and `--line` (`#2C313A → #4E5563`) were retuned
as a **consequence, not cosmetically**: lightening the panel pushed `--muted` to 4.48:1 on
panel and 3.88:1 on panel2, below AA, and `--line` to 1.06:1 (invisible). All 12 text ×
surface pairs were re-verified at every step — zero failures. **Light theme is byte-identical
throughout.**

**A cream shadow inversion (`#ECE7DB`, 13.53:1) was implemented and REJECTED** by the owner as
looking out of place. The measurements are kept in-file so it is not retried blind. Honest
limit: dark mode cannot reach light mode's 16.34:1 drama — 3:1 would need a mid-grey
`~#4F5561`, which stops being a dark theme.

## 5. Bugs found and fixed (BUG-19 … BUG-25)

Two independent pre-release reviews were run in fresh contexts. **Both earned their keep.**

- **BUG-19** `reflectEngine is not defined` on every `settings_changed` — declared in `wire()`,
  called from `wireBridge()`. `reflectBackend` had the identical defect **masked by a
  `typeof … === 'function'` guard**, so it sat silently dead instead of throwing.
- **BUG-20** active nav icon still jumped scale under `prefers-reduced-motion`.
- **BUG-21** `LP.motion.close()`'s uncancelled 300 ms fallback could hide a just-REOPENED
  overlay; the `finished` flag is per-invocation and provably cannot see a stale sibling.
- **BUG-22** `#focus-pill` fought its own inline centering transform — **the same defect class
  already fixed for the toast in §4.7 of the prior handoff**, missed on a second element.
- **BUG-23** the UI stopped accepting clicks mid-job: the 500-line log cap bounded MEMORY but
  not WORK — every `log_line` re-rendered the whole panel including all 500 lines. Renders
  now coalesce per `requestAnimationFrame`.
- **BUG-24** the new slide grid replayed its entrance on every interaction (unconditional
  `.lp-anim-in` + wholesale `innerHTML` rebuild), made worse by Keep/Reject auto-advance.
- **BUG-25** two `AssetResolver` instances could tear the same poster file: `_pending` is
  per-instance and `main.py` owns a second resolver, while all three write sites used a
  DETERMINISTIC temp name. Fixed with unique temp paths + a module-level in-flight set.

## 6. Owner-requested behaviour shipped

- **ETA replaces elapsed.** Non-obvious bug: stages run in PARALLEL, so `next(active)` picked
  Transcribe at 0% while Detect slides was at 42% — the percentage stuck at 33% and the ETA
  climbed forever. Now sums every in-flight stage and shows that same fine-grained percent.
- **Grid/List works.** It was inert markup (two `<span>`s, no id, no handler) that also
  mislabelled itself, since the only layout that existed was the row one. Grid = image tiles
  (new default), List = compact rows. Both share `finishSlides()`.
- **Keep/Reject advance** to the next slide; the bridge call fires with the ORIGINAL index.
- Repair button no longer clipped (the new 3 px shadow spilled past a content-width row).

**Tooling built this session, worth reusing** (session scratchpad — copy out if wanted):
- `cdp.py` — stdlib-only raw-websocket CDP client. `websockets`/`websocket-client` are NOT in
  the venv and `pip install` is off-limits, so this is the only way to drive the app.
- `watch.py` — live console/exception/failed-request monitor writing timestamped JSONL. This
  is what caught BUG-26's smoking gun.

**Hard-won gotchas:**
- **Always canary-validate an error listener.** "Zero console errors" is unfalsifiable
  otherwise. One run's clean result was discarded because its canary failed.
- **Attach AFTER `boot()` completes** — gate on a real readiness signal. An early attach once
  produced a meaningless clean pass.
- **`import_video` is NOT a `@Slot`** — it is the native drop entry point, so
  `lpBridge.call('import_video', …)` silently resolves `null`. The only JS-reachable local
  import is `browse_video` (an OS dialog). Seeding a `Job` directly gets it into the queue but
  NOT active; `open_job` is what activates it.
- **Balanced brace and `/* */` counts do NOT prove CSS validity.** Comment prose left after a
  closing `*/` silently kills the following rules with both counts balanced. That happened
  twice — once presenting as "the nav icons have no motion". Use a comment-stripped
  stray-prose check.
- **Never use backticks inside a `bash -c` string** — command substitution ate a word out of a
  source comment.
- The `code-review-graph` pre-commit hook crashes with a `UnicodeEncodeError` printing its
  summary panel (cp1252 vs box-drawing chars). Cosmetic — the graph updates and the commit
  succeeds. Recurs every commit; `PYTHONIOENCODING=utf-8` would likely silence it.
