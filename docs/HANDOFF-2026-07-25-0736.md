## 1. What this project is

LecturePack turns lecture recordings into study packs — slides, transcript, quizzes,
flashcards, exports — entirely locally, no account and no telemetry. Windows desktop app:
a PySide6 `QWebEngineView` shell (`app/desktop/`) hosting a vanilla-JS UI (`app/ui/`) over
QWebChannel, driving the `lecturepack/` engine (whisper.cpp + ffmpeg + OpenCV).
**Published release: `v0.9.0-beta.3`**, live and non-prerelease on GitHub. This session's
work is **committed to `feat/cuda-engine` but NOT released** — the published binary
predates all of it.

## 4. Architecture & decisions

**Workspace ownership (the session's most structural change).** `LP.state.jobId` owns the
workspace; per-lecture blobs cache in `LP.byJob`; `emptyWorkspace()` makes "nothing loaded"
*structurally* empty rather than merely uncleaned. The backend is authoritative:
`_set_active_job()` is now the **only** place `current_job` is assigned (a test enforces
this across all 10 former assignment sites) and it emits a new `active_job` signal.
Separately, `_emit()` — a single existing chokepoint — stamps every job-scoped payload with
its owning job id, and `ownsPayload()` drops payloads belonging to another lecture. That
second half kills a race ownership alone misses: a slow signal from the *previous* lecture
landing after a switch used to silently repaint over the new one.

**Design tokens.** New `--on-signal` / `--green-fill` / `--red-fill` (accessibility) and
`--motion-fast/medium/slow` + one easing curve (motion). `app.css` carries an explicit "do
not improve values" header note, so these are **additive only — no pre-existing value was
changed.** Motion follows the doctrine's PRODUCT register: subtle, fast (120–240ms), one
curve everywhere, no perpetual motion.

### Rejected alternatives (do not re-test these)

- **Darken `--orange` and keep white text** → rejected: dilutes the brand colour and needs
  a different darkening per fill. Near-black ink on the fill is AA *and* more
  neobrutalist.
- **Retune `--green`/`--red` for fills** → rejected *after checking usage*: both are also
  TEXT colours on soft badge backgrounds, so retuning them would have broken the badges.
  Hence the separate `*-fill` tokens.
- **Wipe all workspace blobs on every job change** → rejected: flickers, loses instant
  switch-back, and does **not** fix the late-signal race.
- **`overflow-x:auto` on `.lp-main`** for the review overflow → rejected: a horizontal
  scrollbar in a workspace pane is worse than a reflow.
- **Emptying the preview-mode demo job seed** → rejected: it's what makes the README
  screenshot pipeline work, and a live bridge overwrites it (BUG-07, deferred).
- **Per-modal `stopPropagation`** for the shortcut bug → rejected: every new modal would
  have to opt in. A central guard in the one global handler covers future modals free.

### Gotchas discovered (also see BUG_LIST.md lessons 1–7)

1. **Inline styles beat class rules.** The design markup carries layout as inline styles, so
   any responsive override needs `!important`. A media query that "does nothing" is usually
   this. Cost me one wrong attempt on BUG-03.
2. **A contrast finding is usually systemic.** BUG-05 was reported as one button; it was
   five fills across both themes, reaching the DOM three ways (inline styles, CSS classes,
   selected-state ternaries). A single-pattern sweep silently left 9 elements failing —
   only a browser audit caught them.
3. **QtWebEngine/browser caches `app.css`/`app.js` aggressively.** Verifying UI edits on a
   port already visited shows the OLD file and will make you debug a phantom. Serve on a
   **fresh port** each time. This wasted real time twice.
4. **`setActiveJob` snapshots the outgoing lecture into `byJob`**, so any "delete the cache
   entry" must happen **after** deactivating. This bit twice — once in the single-delete
   path (`0baf70e`) and again in the bulk branch (`427f0c9`), which repeated the identical
   mistake. Ordering test now covers both branches.
5. **`urllib.parse.quote` defaults to `safe='/'`**, so a separator in an id is not escaped.
   Fixed in `poster_url` with `safe=''` as defence in depth.

**PROMOTE TO SKILLS FOLDER** (verbatim candidates, all verified in this project):

1. **PROMOTE TO SKILLS FOLDER — Verifying web-UI edits: always use a fresh port.**
   QtWebEngine and the in-app browser cache `app.css`/`app.js` aggressively. Re-visiting a
   port you already loaded serves the OLD asset and you will debug a phantom (observed
   twice: computed tokens read empty, and a page ran a script version from before the
   edit). Start `http.server` on a new port per verification round, and confirm the served
   bytes contain your change (`curl … | grep`) before trusting any measurement.

2. **PROMOTE TO SKILLS FOLDER — A contrast finding is a palette audit, not a one-line fix.**
   When one colour pair fails WCAG, compute the whole palette in both themes before
   fixing, and grep every way the foreground can be set (inline styles, CSS classes,
   conditional ternaries in JS). A reported "one button at 2.82:1" was five fills across
   two themes; a single-pattern sweep left 9 elements still failing.

3. **PROMOTE TO SKILLS FOLDER — Inline styles outrank class rules.** When a design system
   ships layout as inline styles, responsive overrides need `!important`, and a media query
   that appears to do nothing is usually this. Comment *why* the `!important` is there so it
   doesn't read as laziness.

4. **PROMOTE TO SKILLS FOLDER — UI state with no owner rots.** Any screen data must answer
   two questions before it ships: which entity owns this, and what does it look like when
   there is none? Two separate bugs in one project (a fake in-progress job on first run;
   workspace screens showing other records' data) were the same disease at different
   altitudes. Add a freshness stamp at the emit chokepoint too — ownership alone doesn't stop
   a late signal from the previous entity repainting over the new one.

5. **PROMOTE TO SKILLS FOLDER — Extract the shared path before adding a bulk variant.**
   Adding "delete many" next to "delete one" duplicates the risky part. Extract the single
   operation, have both call it, and assert in a test that neither reimplements it. The
   ordering bug in the single path was reproduced verbatim in the bulk branch when they
   were written separately.
