# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — existing static HTML/CSS/JavaScript shell |
| Preset | not applicable |
| Component library | none; QtWebEngine renders the shipping `app/ui` shell |
| Icon library | inline SVG icons already in `index.html` |
| Font | Space Grotesk for UI copy; JetBrains Mono for compact labels, status, and numeric metadata |

**Preservation source:** `04-CONTEXT.md` D-17 and `app/ui/app.css` are authoritative. Do not introduce a second component, token, theme, or animation system. Preserve the beta-5 hard dark-shadow, 2px-border, embedded-press character and its existing CSS custom properties.

**Primary Home focal point:** The existing empty-state message and normal `Add lecture` next step are the primary Home hierarchy. `Start guided demo` is a secondary onboarding path. Phase 4 must not introduce competing accent, motion, or card emphasis that reverses that hierarchy.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon/text separation and tight status details |
| sm | 8px | Compact control gaps and tooltip offset |
| md | 16px | Default control/card padding and narrow-layout gutter |
| lg | 24px | Desktop section padding and tour-card edge inset |
| xl | 32px | Major section gaps and normal card separation |
| 2xl | 48px | Page-level vertical separation |
| 3xl | 64px | Large page-level breathing room only |

Exceptions: Existing beta-5 2px borders, 3px hard-shadow offset, 9px/12px/14px component radii, 11px scrollbar, and 44px minimum pointer target where the current control pattern allows it. At every viewport size, retain a 16px minimum readable gutter for stacked content; the tour card may use the existing 16px inset at `<=640px`.

**Responsive rule:** Do not impose a Phase-4 minimum window size. Below the existing desktop breakpoints (1220px, 820px, and 640px where applicable), stack secondary controls below their primary content, permit vertical page scrolling, and keep every required action reachable. Required actions may never be clipped or require horizontal scrolling.

## Typography

Use only these four size roles for Phase-4 additions; preserve existing beta-5 instances that already use them.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Meta / tooltip | 12px | 600 | 1.4 |
| Body | 14px | 400 | 1.5 |
| Section heading / control label | 20px | 600 | 1.2 |
| Page display | 28px | 600 | 1.2 |

Only weights 400 and 600 are permitted for new Phase-4 UI. Use tabular figures only for live numeric values so backend progress/count updates do not shift adjacent layout. Long model names remain a single line, `overflow: hidden`, `text-overflow: ellipsis`, and `white-space: nowrap`; they never resize the containing field.

## Color

All values come from the existing root CSS variables; switch the root `data-theme` attribute rather than applying individual inline palette changes.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `--bg #F3F0E8`; Dark `--bg #16191F` | Window/page background and the app root |
| Secondary (30%) | Light `--panel #FFFFFF` / `--panel2 #F7F4ED`; Dark `--panel #1F242C` / `--panel2 #262C35` | Cards, sidebar, navigation, modal/tour card, secondary surfaces |
| Accent (10%) | Light `--orange #EF5A1E`; Dark `--orange #FF6C36` | Primary guided-tour actions, active tour progress marker, spotlight border/arrow, active navigation/tab signal, and the existing demo callout only |
| Destructive | Light `--red #BA3024`; Dark `--red #FF6E5E` | Exit/irreversible or destructive actions and failure status only |

Accent reserved for: primary guided-tour progression, active tour state, spotlight geometry, active navigation/tab state, and existing demo emphasis. Do not use accent merely to decorate normal backend updates. `--blue` remains the existing focus/secondary-action color, not a destructive or global-primary replacement.

**Theme contract:** A fresh profile starts Light. Apply the persisted theme before the first visible WebEngine frame. A user theme action performs one atomic root-theme mutation and immediately persists the selection; no global Save action is required. Do not crossfade the window or tween individual palette properties. The existing embedded button press may animate, but every open gate, dialog, tour surface, and underlying page must adopt the palette in the same frame.

## Motion and Interaction Contract

- Preserve beta-5 motion tokens exactly: 90ms hover/press, 110ms snap, 140ms entrance/seat, 160ms color/state, and 220ms maximum progress/completion movement; retain the established spring and soft-opacity curves. Do not add bounce, scale a bordered surface, viewport crossfades, or new one-off keyframes.
- Page entrance animation is navigation-only: run it once after the user navigates to a different page. Re-clicking the active navigation control, a backend event, option change, status/log/progress update, or any state render must update in place and must not replace/reclass the page root or replay its entrance.
- Closing the runtime setup gate, guided-tour surface, dialog, dropdown, or another overlay returns to the unchanged underlying page without a page entrance replay or layout jump.
- Preserve existing micro-interactions only on the directly changed control. Preserve hard shadows and pressed/embedded movement; do not flatten, modernize, or reduce the beta-5 visual character.
- Keep standard motion in this milestone. Do not add or expand reduced-motion behavior beyond existing beta-5 rules.
- Do not use a full-viewport SVG mask. Keep the QtWebEngine-safe CSS spotlight: pointer-transparent overlay/dimmer and spotlight box, with only the real highlighted control and tour card receiving pointer interaction.

### Overlays, focus, resize, and DPI

- The runtime setup gate remains modal; focus cannot reach normal-app controls while it is active.
- During a guided step, keyboard focus cycles only among the highlighted real action and tour controls. The Exit demo action is always keyboard reachable. Focus must not leak into dimmed, unrelated controls.
- On resize, scroll, monitor move, or DPI/scale change, measure the live target and viewport again before the next paint; continuously reposition the CSS spotlight and clamp the tour card inside the viewport. Do not fade, restart the step, replay page motion, or reset tour progress.
- If a target is outside the viewport, scroll the minimum distance needed to reveal the real control, then measure and position the spotlight.
- Long local-model values expose their full text in a small anchored tooltip on both pointer hover and keyboard focus; hide it when that hover/focus leaves. The tooltip must collision-adjust inside the viewport and must not resize or reflow the source field.
