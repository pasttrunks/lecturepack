<objective>
Build the phase's shipping artifact once, freshly, after every change has landed — then physically verify
on real hardware the things no test in this repository can prove, and close `01-EVIDENCE.md`.

This plan closes the ROADMAP "Approval/evidence gate" line. Six `must_haves` entries across Plans 01-01,
01-04, 01-05 and 01-06 are recorded as `verification: backstop` and name this plan as their owner:
01-01's `## Size — after cuts` table and the completion of Success Criterion 1's reconciliation; 01-04's
post-cut packaged smoke and its packaged WebEngine render proof; 01-05's installed-build two-process
raise-and-focus proof and its installed-build icon-visible proof; and 01-06's cold-feedback observation
plus its separately-measured cold and warm launch times. Plan 01-07's four UI-SPEC backstop rows are
observed in the same session, because they are observations of this same single installed build and a
second build would not be the artifact under test.

Wave 4 and this dependency set are not bookkeeping. `app/ui/` is bundled into the package as PyInstaller
`datas`, so a build produced before Plan 01-07 lands would ship the previous overlay and could prove
nothing about the first-run checklist. `app/packaging/lecturepack.iss` carries Plan 01-05's
AppUserModelID, so an installer built before that lands cannot prove the taskbar icon. The build has to
be last.

**The honesty requirement is the point of this plan.** `01-CONTEXT.md` `<canonical_refs>` cites beta-6's
Phase 5 release gate as a counter-example this phase must not repeat: it was certified on evidence never
gathered on a physical machine, and it named no machine. So every claim requiring a human to build,
launch and read a number is authored as a `{statement, verification: backstop}` marker and sits behind a
blocking `checkpoint:human-verify` task — never as a plain truth a verifier could pass by reading source.
Plan 01-05 already owns one such checkpoint, for the *diagnosis* of the icon cause before the fix. This
plan owns the second pass: the installed build, after the fix.

This plan writes no source code. Its only edited file is `01-EVIDENCE.md`.

Purpose: make the phase's claims true because someone measured them, on a named machine, in one sitting.
Output: one fresh installer, a filled and reconciled size table, a green post-cut packaged smoke, and a
closed evidence file with an explicit NOT-verified ledger.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| freshly built installer → physical machine | The installer is executed on the developer's real Windows machine, writing to a per-user location and creating uninstall registry state. |
| acceptance runs → the user's real data directory | A packaged launch performs startup reconciliation that rewrites lifecycle state, so pointing one at `~/LecturePackData` would mutate real jobs. |
| recorded evidence → release decision | Every number in `01-EVIDENCE.md` is what a future release gate will trust. A number recorded without a measurement behind it is the beta-6 failure mode. |
| Start Menu shortcut → Windows shell identity | The AppUserModelID association is what the taskbar observation actually tests, so that observation must come from the shortcut, not from a bare executable launch. |
