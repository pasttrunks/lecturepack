<objective>
Stop a second launch from looking like a failed launch, and make the taskbar icon appear — after
determining, on a packaged build, which of the two candidate causes is actually responsible.

**D-18** — a second launch raises and focuses the existing window rather than exiting silently; silent
exit is indistinguishable from a failed launch, which is what produced the owner's repeated clicking.
**D-19** — the guard runs before `RuntimeBootstrapService.assess()`; a guard after it would let a
second process sit invisible for up to 90s. **D-20** — the blank taskbar icon has two candidate
causes and the phase must determine which before fixing: (a) no `SetCurrentProcessExplicitAppUserModelID`
call exists anywhere in `app/`, and (b) `setWindowIcon` at `app/desktop/main.py:107` is guarded by an
`os.path.exists` check with no else-branch. The `.ico` is present in the built output and stamped into
the exe, which makes (a) the stronger suspect — but D-20 requires confirming on the packaged build
rather than assuming. **D-21** — whatever the cause, the missing-icon path must stop failing silently.

This plan depends on Plan 01-01 because D-20's diagnosis needs a packaged build to inspect, and Plan
01-01 produces one. The icon behavior is unaffected by Plan 01-04's Qt cuts, so diagnosing against the
pre-cut build is valid.

`01-CONTEXT.md` leaves the single-instance mechanism and its wire format to discretion, provided it
satisfies D-18 and D-19 and cleans up after a crash. `01-RESEARCH.md` recommends `QLocalServer`/
`QLocalSocket` because it is the only candidate that also gives the second process a channel to ask
the first to raise — `QSharedMemory` and a named mutex only detect duplication. RESEARCH Open Question 1
flags that `QApplication` likely must exist before a `QLocalSocket` probe; the ordering below satisfies
D-19 either way, and the plan requires verifying it with a real two-process test rather than assuming.

Purpose: remove the ambiguity that made a slow launch look like a broken one, from both directions.
Output: a single-instance guard module, correct process identity, and a non-silent icon path.
</objective>

  <behavior>
    - `SingleInstanceGuard(name).acquire()` returns "primary" for the first caller and "secondary" for a second caller while the first holds the endpoint.
    - A secondary caller's `signal_existing()` delivers exactly the fixed raise sentinel and returns success; the primary's registered callback fires once per delivery.
    - The primary's callback is not invoked for any payload other than the exact sentinel; a test sends a different byte string and asserts the callback did not fire.
    - The received payload is never passed to `json.loads`, `eval`, `exec`, `pickle`, or any other deserializer; a test asserts the handler compares against a literal and nothing more.
    - A bounded read size is enforced, so a peer cannot force unbounded buffering by streaming bytes.
    - After the primary releases the endpoint, a fresh `acquire()` returns "primary" again — the endpoint is reusable.
    - A stale endpoint left behind with no listener is reclaimed: a test simulates the stale case and asserts `acquire()` returns "primary" rather than falsely reporting "secondary".
    - When the IPC primitive raises or is unavailable, `acquire()` returns "primary" (fail-open on launch) rather than raising or returning "secondary" — an OS-integration failure must never prevent the app from starting.
    - The endpoint name is a fixed literal derived from the application identity, not from `sys.argv`, an environment variable, or any caller-supplied string.
  </behavior>

    Create `app/desktop/single_instance.py`. Keep it a small, self-contained module in the desktop shell
    layer — per `01-RESEARCH.md`'s Architectural Responsibility Map, this is shell-level process

    Define:
    - `SINGLE_INSTANCE_ENDPOINT` — a fixed literal endpoint name derived from the application identity
      (use `version.APP_NAME` plus a stable suffix). Never build it from `sys.argv` or an env var.
    - `RAISE_SENTINEL` — one short fixed ASCII literal, the entire wire protocol. There is no message
      format, no versioning, no fields: the channel carries one word and nothing else.
    - `MAX_MESSAGE_BYTES` — a small bound (a few dozen bytes) on how much is ever read from a peer.
    - `class SingleInstanceGuard` with:
      - `__init__(self, endpoint=SINGLE_INSTANCE_ENDPOINT)`
      - `acquire(self) -> str` — returns `"primary"` or `"secondary"`. Probe with a `QLocalSocket`
        connect attempt and a short bounded `waitForConnected` timeout; if it connects, another
        instance owns the endpoint and this is `"secondary"`. Otherwise listen with a `QLocalServer`.
        Before listening, call `QLocalServer.removeServer(endpoint)` to reclaim a stale endpoint left by
        a crashed prior instance — this is the crash-cleanup requirement in CONTEXT.md's discretion
        note. Wrap the whole body so any exception yields `"primary"`.
      - `signal_existing(self) -> bool` — connect, write `RAISE_SENTINEL`, flush, wait bounded, close.
      - `set_raise_handler(self, callback)` — register the callable invoked when a valid sentinel
        arrives. The connection handler must read at most `MAX_MESSAGE_BYTES`, compare the bytes to
        `RAISE_SENTINEL` with an equality test, invoke the callback on a match, and otherwise drop the
        connection. No parsing, no deserialization, no logging of peer-supplied bytes.
      - `release(self)` — close the server and remove the endpoint.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unprivileged local process → single-instance IPC endpoint | Any process running as the same user can connect to the `QLocalServer` named pipe and send bytes. This is the one new attack surface in this plan. |
| Windows shell → application identity | The AUMID associates the running process with an installed shortcut; a mismatch causes identity confusion in the taskbar and Start Menu. |
| filesystem → icon resolution | The `.ico` path is resolved differently in frozen and source builds; a missing file currently disappears silently. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05-01 | Spoofing | single-instance IPC endpoint accepting arbitrary commands | high | mitigate | The entire wire protocol is one fixed ASCII sentinel compared by byte equality. The handler reads at most `MAX_MESSAGE_BYTES`, never calls `json.loads`, `eval`, `exec` or `pickle`, and drops any non-matching connection. A local peer's maximum achievable effect is raising a window that the user owns anyway. Tests assert the non-sentinel payload does not fire the handler. |
| T-01-05-02 | Elevation of Privilege | widening the endpoint's access scope | high | mitigate | `QLocalServer.setSocketOptions` is left at its default, which on Windows scopes the named pipe to the current user. No world-accessible or other-user option is set, and the endpoint name is a fixed literal never derived from `sys.argv` or an environment variable. |
| T-01-05-03 | Denial of Service | stale endpoint locking the user out of launching | high | mitigate | `acquire()` calls `QLocalServer.removeServer(endpoint)` before listening to reclaim a crashed prior instance's endpoint, and the whole body degrades to `"primary"` on any exception — the guard can never be the reason the app fails to start. Tests cover both the stale case and the raising-primitive case. |
| T-01-05-04 | Denial of Service | unbounded read from a hostile local peer | medium | mitigate | `MAX_MESSAGE_BYTES` bounds every read, and `waitForConnected`/`waitForReadyRead` use short bounded timeouts so a silent peer cannot stall startup. |
| T-01-05-05 | Tampering | AUMID-to-shortcut mismatch causing identity confusion | medium | mitigate | The literal is defined once per file and asserted byte-identical across `main.py` and `lecturepack.iss` by a test; it contains no version component, so a version bump cannot orphan a pinned icon. Per-user install to a fixed predictable location (`PrivilegesRequired=lowest`) means the install path is stable. |
| T-01-05-06 | Repudiation | silent icon-resolution failure | medium | mitigate | D-21's non-silent path: both the window-icon and tray-icon guards report the path they tried, so a future packaging change that stops shipping the `.ico` leaves a trace instead of vanishing (the same class of defect BUG-04 recorded — markup with no writer, undetected for months). |
| T-01-05-07 | Denial of Service | AUMID call raising on a non-Windows or restricted host | low | mitigate | Wrapped in `if sys.platform == "win32"` plus `try/except Exception: pass`, matching `win_integration.py`'s stated rule that a COM/shell failure must never break the frozen exe. |
| T-01-05-SC | Tampering | package-manager installs | low | accept | No npm/pip/cargo installs; `ctypes` and `PySide6.QtNetwork` are already present. `01-RESEARCH.md` § Package Legitimacy Audit records the audit as not applicable, and § Standard Stack explicitly rejects adding `comtypes`/`pywin32` as PyInstaller hazards. |
