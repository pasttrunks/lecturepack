<objective>
Show the window first, then run runtime validation behind honest itemized progress — without opening a
hole in the admission contract.

**D-06** fixes the root cause and forbids re-litigating it: `RuntimeBootstrapService.assess()` is called
synchronously on the UI thread in `Backend.__init__` (`app/desktop/bridge.py:119`), before the window is
shown. On a fresh profile it takes the full path — `ffmpeg -version`, `ffprobe -version`, and a real
staged whisper-cli transcription, each bounded at 30s — so worst case is ~90s with nothing on screen.
**D-08** requires fixing both sides: show the window first *and* reduce validation cost. Plan 01-03
already did the cost half (parallelized probes). This plan does the sequencing half. **D-09** requires
progress that names the real work, not a generic bar — the distinction between honest feedback and the
splash screen the owner explicitly ruled out. **D-07** requires cold and warm launches be treated as the
architecturally different paths they are, so the UI can render itemized checking on the full path and
nothing at all on the light path.

There is a hazard the CONTEXT does not name and this plan must close. `Backend.__getattribute__`
withholds every entry in `_ADMISSION_GUARDED_OPERATIONS` only when `runtime_health_result` is present
*and* not HEALTHY. If deferral leaves that attribute unset, the guard falls through and every guarded
bridge operation becomes reachable before admission. The fix is to assign a pending sentinel result as
the very first statement of `__init__`, so the guard is closed from the first instruction.

Two smaller consequences of deferral also need handling: `ui_ready` currently drives
`self._adapter.on_ui_ready()` and `self._updater.startup_check()`, both of which will not exist yet; and
`main.py:161-164` attaches the window to the adapter inside a bare `try/except: pass`, which will
silently no-op. Both must be re-driven after admission, from inside `bridge.py` — this plan does not
touch `main.py`, which Plan 01-05 owns.

Purpose: make a cold launch legible within seconds without weakening what admission proves.
Output: a deferred, progress-reporting bootstrap and an extended `get_bootstrap()` contract.
</objective>
