<objective>
Build the Python side of the first-run contract before any UI or bridge work depends on it: the
persisted acknowledgement flag, the five-item checklist verdict service, and the probe
parallelization that makes cold startup faster without weakening admission evidence.

This is the interface-first task of the startup/checklist half of the phase. Plans 01-06 (bridge) and
01-07 (UI) both consume the item ids and verdict shape defined here, so it lands first.

Three locked decisions drive it:
- **D-16** — "Setup acknowledged" persists alongside `runtime_health` in `<data_dir>/config.json`, not
  in WebEngine `localStorage`. The existing guided-tour flag is in localStorage and dies with the
  WebEngine profile; this flag must survive that.
- **D-13** — the checklist verifies exactly five things: supported Windows version; bundled FFmpeg and
  ffprobe; bundled Whisper executable and required DLLs; bundled model; writable LecturePack data
  directory. Nothing else. **D-14** — it never downloads or reinstalls anything already bundled, so
  the contract carries no remediation affordance at all.
- **D-10** — parallelizing the three independent probes is permitted; replacing the real staged
  transcription with a weaker liveness check is not. If parallelization alone proves insufficient,
  this plan reports that rather than weakening the check.

Two of D-13's five items have no existing check anywhere in the codebase — supported Windows version
and writable data directory. They are created here as small, injectable, unit-testable predicates.

Purpose: give the bridge and UI a decided, backend-owned verdict to render, and cut cold-start
wall-clock time without touching the admission contract.
Output: a persisted flag, a new `first_run_checklist` service, and a parallelized `_validate_full`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bundled runtime binaries → validation subprocesses | `_validate_full` executes bundled `ffmpeg`, `ffprobe` and `whisper-cli` as argument lists. Concurrency changes when they run, not what runs. |
| `<data_dir>/config.json` → application state | The acknowledged flag is read from a file a user can hand-edit. |
| host OS → checklist verdicts | `sys.getwindowsversion()` and a filesystem writability probe feed a verdict the UI renders. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03-01 | Tampering | admission evidence completeness under parallelization | high | mitigate | Preserve all eight `_FULL_SUCCESS_EVIDENCE_FIELDS` per component and collect via `future.result()` so a worker exception propagates; a dropped future would let incomplete evidence pass `_requires_full` and admit an unvalidated runtime. Tests assert field completeness and exception propagation. |
| T-01-03-02 | Tampering | AD-18 ASCII native-staging boundary | high | mitigate | `WhisperPathStaging` construction, its argument list, and its `try/finally` cleanup are unchanged; the staged model/WAV paths still come from `prepare()` and are never passed as raw Unicode paths to the native CLI. A test asserts cleanup runs on the failure path. |
