<objective>
Implement the two new client states the first-run experience needs — the honest itemized `checking`
progress and the Ready / Needs Attention `checklist` — inside the overlay that already exists.

This plan owns ROADMAP Success Criterion 5 and the UI half of the startup work. Plans 01-03 and 01-06
built the whole backend contract for it: five decided checklist verdicts, a pending flag, a validation
path, a persisted acknowledged flag, per-component progress signals, and an acknowledge slot. None of
it is rendered yet. `app/ui/app.js`, `app/ui/index.html` and `app/ui/app.css` appear in no other plan
in this phase, so this plan is the sole owner of all three.

**D-15** fixes where this lives: the existing WebEngine vocabulary. A native Qt pre-window was
considered and rejected because it would give a new user two visual languages in the first ten seconds.
**D-11** fixes what must not change: the existing overlay is a *failure* gate and every one of its seven
states keeps its current behaviour. **D-12** fixes the new behaviour: a first-ever launch always sees
the checklist, then a Continue action leads onward. **D-17** fixes the demo boundary: the offer becomes
reachable only after the user continues or deliberately skips.

The load-bearing constraint is direction of authority. Per the project's established pattern, the gate
is decided in Python before the UI asks; the UI renders a backend verdict. Every Ready / Needs Attention
mark in this plan comes from the `verdict` field Plan 01-03 computes. Nothing here recomputes health
from component evidence.

`01-UI-SPEC.md` is the design contract and is approved. Its `## UI Considerations` table has 18 covered
rows and 4 backstop rows; all 22 are lifted into this plan's `must_haves`, and the 4 backstops are
observed during Plan 01-08's single installed-build session rather than claimed here.

Purpose: make a healthy first launch legible and reassuring without making it look like an error screen.
Output: two new reducer states, two new overlay sections, and the wiring that routes between them.
</objective>
