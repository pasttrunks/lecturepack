<objective>
Build the measurement instrument this phase's first Success Criterion requires, then record the
pre-cut baseline from one freshly built installer.

ROADMAP Success Criterion 1 demands installer size and installed size as *separate* measured
numbers from *one* freshly built `Setup.exe`, with the largest contributors listed, and the
owner-reported-vs-dev-tree discrepancy resolved and explained rather than averaged. CONTEXT.md's
`<open_measurement>` block makes the same demand and adds that the stale 1.9 GB figure must not be
reused because `app/dist/` may carry build residue.

Nothing in `tests/` measures artifact size today (`01-VALIDATION.md` Wave 0 Requirements, first
item). This plan closes that gap with a reusable script, seeds the phase evidence file, and captures
the baseline before Plan 01-04 rebuilds the tree.

This plan performs no size cuts. It cites D-01 and D-02 only as the audit target list, so the same
predicate can be re-run after Plan 01-04 lands.

Purpose: make the size claim measurable and the discrepancy answerable, so beta-6's failure mode
(a release gate accepted on evidence nobody gathered) cannot repeat here.
Output: a measurement script with unit tests, and `01-EVIDENCE.md` carrying the pre-cut baseline.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build host → filesystem | The measurement script walks trees and runs a real installer, writing to a throwaway directory chosen by the operator. |
| Setup.exe → local machine | `--expand-to` executes the freshly built installer, which writes to a per-user location (`PrivilegesRequired=lowest`) and creates uninstall registry state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01-01 | Tampering | `--expand-to` silent install target | medium | mitigate | Refuse to install into an existing non-empty directory; always run `unins000.exe /VERYSILENT` afterwards and report if absent, so a throwaway install cannot be mistaken for or overwrite a real one. |
| T-01-01-02 | Elevation of Privilege | installer invocation | low | mitigate | Invoke the installer as an argument list, never `shell=True`, matching the project's existing external-process rule; pass no elevation switches. |
| T-01-01-03 | Denial of Service | `tree_size` on a path with symlink loops | low | mitigate | Walk with a non-following traversal and skip non-regular entries rather than recursing into links. |
| T-01-01-04 | Information Disclosure | `01-EVIDENCE.md` machine identity fields | low | accept | Only OS build number, CPU model and git commit are recorded; no user paths outside the repo, no credentials, no personal data. This is the minimum needed to make the measurement re-checkable. |
| T-01-01-SC | Tampering | package-manager installs | low | accept | No npm/pip/cargo installs occur in this plan; `01-RESEARCH.md` § Package Legitimacy Audit records the audit as not applicable because the phase adds zero external packages. PyYAML is deliberately not introduced. |
</threat_model>
